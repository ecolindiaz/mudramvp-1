# Agent Lab - Complete Implementation Summary

## Overview
The Agent Lab system enables AEO/GEO optimization agents to connect to user GitHub repositories and make automated code changes to improve AI visibility. This document summarizes the complete implementation.

## ✅ Completed Implementation

### 1. Database Schema (Prisma)
Created 4 new models in `mudra-app/prisma/schema.prisma`:

#### DeployedAgent
- Tracks deployed agent instances per brand profile
- Links to GitHub repository
- Status tracking (deploying, active, paused, failed)
- Fields: agentType, agentName, githubRepoName, githubBranch, lastExecutedAt

#### AgentTask
- Records of agent execution history
- Task types: analyze, optimize, create_pr
- Status tracking (pending, running, completed, failed)
- Input/output stored as JSON
- Links to DeployedAgent

#### AgentOptimization
- Individual code optimizations generated by agent
- Types: schema_markup, faq_section, headers, meta
- Stores before/after code, file paths
- Status: pending, applied, pr_created, merged, failed
- Tracks PR URLs and impact level

#### GitHubIntegration
- Secure storage of GitHub OAuth credentials
- AES-256-GCM encrypted access tokens
- Links to User model (unique per user)
- Stores GitHub username, user ID, avatar

### 2. API Endpoints

#### Agent Deployment
- **POST /api/agents/deploy** - Deploy new agent instance
- **GET /api/agents/deploy** - List deployed agents by brand
- Creates initial "analyze" task on deployment

#### Agent Execution  
- **POST /api/agents/execute** - Execute agent actions
- Supports 3 actions:
  - `analyze` - Scan website for optimization opportunities
  - `optimize` - Generate code changes for pending optimizations
  - `create_pr` - Create GitHub pull request with all applied changes
- Uses real Mastra agent (aeoGeoOptimizerAgent)

#### GitHub Integration
- **POST /api/integrations/github** - Connect GitHub account
- **GET /api/integrations/github** - Get connection status
- **DELETE /api/integrations/github** - Disconnect GitHub
- **GET /api/integrations/github/repositories** - List user repos
- **GET /api/auth/github/callback** - OAuth callback handler

### 3. Agent Implementation

#### Core Agent: aeoGeoOptimizerAgent
Location: `mudra-app/mastra/agents/aeo-geo-optimizer.ts`

**Tools:**
- `analyzeCodebase` - Scans website structure for AEO/GEO issues
- `generateSchemaMarkup` - Creates JSON-LD schema
- `calculateAeoScore` - Calculates visibility score

#### Agent Workflow
```
1. Deploy Agent → Creates DeployedAgent record
2. Analyze → Agent scans website, creates AgentOptimization records
3. Optimize → Agent generates code for each optimization
4. Create PR → Commits changes to GitHub, creates pull request
```

#### Implementation Details
- Uses Mastra Framework (@mastra/core)
- E2B Code Interpreter for sandbox execution
- Prompt-based tool invocation
- JSON response parsing with text fallback
- Console logging with [Agent] prefix for debugging

### 4. GitHub Integration

#### OAuth Flow
1. User clicks "Connect GitHub" in Agent Lab
2. Redirect to GitHub OAuth consent screen
3. GitHub redirects to /api/auth/github/callback
4. Exchange code for access token
5. Store encrypted token in GitHubIntegration table
6. Redirect back to Agent Lab

#### PR Creation Workflow
```
1. Get pending optimizations with status='applied'
2. Decrypt GitHub access token
3. Get repository default branch
4. Create new branch (aeo-geo-optimization-{timestamp})
5. For each file:
   - Fetch current content
   - Apply optimizations (schema in <head>, others in <body>)
   - Commit changes to new branch
6. Create pull request with detailed description
7. Update optimizations to status='pr_created'
```

#### Security
- **Encryption:** AES-256-GCM algorithm
- **Key:** 32-byte hex key from GITHUB_TOKEN_ENCRYPTION_KEY env var
- **Format:** `iv:authTag:encryptedData`
- **Scope:** repo (full repository access)

## 🛠️ Technical Stack

- **Backend:** Next.js 15.3.3 API Routes
- **Database:** PostgreSQL (Supabase) with Prisma ORM
- **Agent Framework:** Mastra (@mastra/core)
- **Sandbox:** E2B Code Interpreter
- **OAuth:** GitHub OAuth Apps
- **Encryption:** Node.js crypto (AES-256-GCM)
- **Validation:** Zod schemas
- **Authentication:** NextAuth.js
- **Frontend:** React 19 with TypeScript
- **Toast Notifications:** Sonner

## 🔐 Security Considerations

1. **Token Encryption:** All GitHub access tokens encrypted at rest
2. **Session Auth:** All API endpoints require valid NextAuth session
3. **Scope Limitation:** OAuth requests only "repo" scope (no admin access)
4. **Input Validation:** Zod schemas validate all API inputs
5. **CSRF Protection:** NextAuth handles CSRF tokens
6. **SQL Injection:** Prisma ORM prevents SQL injection
7. **Rate Limiting:** Should add rate limiting to API endpoints
8. **Audit Logging:** Should log all agent actions for audit trail

## 📝 Notes

- Agent execution is asynchronous - tasks run in background
- Optimizations are applied in batches of 5
- PR creation groups changes by file path
- Schema markup inserted in <head>, other optimizations in <body>
- Agent logs to console with [Agent] prefix for debugging
- GitHub API rate limit: 5000 requests/hour for authenticated users
